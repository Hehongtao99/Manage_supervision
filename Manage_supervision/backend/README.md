# 学生管理系统后端文档

本文档详细介绍了学生管理系统后端的架构和各个组件功能。

## 项目结构概览

后端采用Spring Boot框架开发，使用了MVC架构模式，主要包含以下模块：

```
backend/
├── src/main/java/com/example/auth/
│   ├── annotation/    - 自定义注解
│   ├── aspect/        - 切面类（AOP）
│   ├── config/        - 配置类
│   ├── controller/    - 控制器层
│   ├── dto/           - 数据传输对象
│   ├── entity/        - 实体类
│   ├── exception/     - 异常处理
│   ├── interceptor/   - 拦截器
│   ├── repository/    - 数据访问层
│   ├── security/      - 安全相关
│   ├── service/       - 服务层
│   ├── util(s)/       - 工具类
│   └── AuthApplication.java - 应用程序入口类
```

## 核心文件说明

### 入口类

#### `AuthApplication.java`
- **功能说明**：项目的启动入口类，包含main方法
- **主要内容**：使用`@SpringBootApplication`注解标记的主类，通过SpringApplication.run()方法启动整个应用程序
- **技术要点**：Spring Boot自动配置，组件扫描，依赖注入的启动点

### 注解 (annotation)

#### `RequireRole.java`
- **功能说明**：自定义注解，用于方法级别的角色权限控制
- **主要内容**：定义了一个运行时注解，可以标记在控制器方法上，指定访问该方法需要的角色权限
- **使用场景**：在需要进行角色权限控制的API接口方法上添加此注解，如`@RequireRole("ADMIN")`表示只有管理员角色才能访问
- **实现原理**：通过拦截器和AOP技术，在请求到达控制器方法前检查用户角色

### 拦截器 (interceptor)

#### `AuthInterceptor.java`
- **功能说明**：权限校验拦截器，负责拦截HTTP请求并进行权限验证
- **主要内容**：实现了HandlerInterceptor接口，拦截请求并检查用户是否有权限访问特定的API端点
- **主要功能**：
  - 验证JWT令牌的有效性
  - 检查用户是否具有访问特定接口所需的角色权限
  - 结合RequireRole注解使用，实现方法级别的权限控制
- **工作流程**：
  1. 在preHandle方法中截获请求
  2. 从请求头获取JWT令牌
  3. 验证令牌并解析用户信息
  4. 检查方法上的RequireRole注解
  5. 验证用户是否拥有所需角色
  6. 根据验证结果决定是否允许请求继续

### 配置类 (config)

#### `AsyncConfig.java`
- **功能说明**：异步任务配置类
- **主要内容**：配置异步任务执行器，用于处理系统中的异步操作
- **配置项**：线程池大小、队列容量、线程名称前缀、拒绝策略等
- **应用场景**：处理耗时操作如邮件发送、数据导出、复杂计算等，避免阻塞主线程

#### `DataInitializer.java`
- **功能说明**：数据初始化器，负责在应用启动时初始化必要的基础数据
- **主要内容**：创建默认角色、管理员账户等系统必需的初始数据
- **执行时机**：应用启动时自动执行，通过`@PostConstruct`注解或者实现`CommandLineRunner`接口实现
- **主要功能**：初始化角色数据（管理员、教师、学生、家长等）、创建默认管理员账户、初始化系统参数

#### `WebConfig.java`
- **功能说明**：Web应用配置类
- **主要内容**：配置跨域(CORS)、拦截器、资源处理器等Web相关设置
- **主要配置**：
  - 跨域(CORS)配置：允许的来源、HTTP方法、请求头等
  - 拦截器注册：将AuthInterceptor注册到Spring MVC
  - 静态资源映射：配置上传文件访问路径
  - 自定义参数解析器：如日期格式解析器等

#### `WebSocketConfig.java`
- **功能说明**：WebSocket配置类
- **主要内容**：配置WebSocket相关设置，用于实时通信功能（如聊天、通知等）
- **主要配置**：
  - WebSocket端点注册
  - 消息代理配置
  - 允许的客户端来源
  - STOMP协议支持
  - 消息大小限制
- **应用场景**：实时聊天、即时通知、实时协作等功能

### 数据传输对象 (DTO)

DTO层包含大量的数据传输对象，这些对象用于在不同层之间传递数据，尤其是在控制器和服务层之间。它们的命名通常与实体类相似，但包含`DTO`后缀，如`UserDTO`。

主要DTO类型包括：
- **请求DTO**：如`TaskRequest`、`NotificationRequest`等，用于接收客户端请求数据
- **响应DTO**：如`ApiResponse`、`NotificationResponse`等，用于向客户端返回数据
- **数据传输DTO**：如`UserDTO`、`ClassDTO`等，用于在不同层之间传输数据
- **统计DTO**：如`DashboardStats`、`SupervisorDashboardDTO`等，用于传输统计数据

## 核心业务流程

### 用户认证流程
1. 用户通过AuthController提供的登录接口提交用户名和密码
2. 系统验证用户名和密码
3. 验证成功后，生成JWT令牌返回给客户端
4. 客户端在后续请求中携带JWT令牌进行身份验证

### 权限控制流程
1. 用户请求受保护的API
2. AuthInterceptor拦截请求，验证JWT令牌
3. 如果方法标记了@RequireRole注解，拦截器检查用户是否具有所需角色
4. 权限验证通过后，请求才能继续处理

### 消息通知流程
1. 系统事件触发通知生成（如新作业发布、成绩更新等）
2. 通知信息保存到数据库
3. 通过WebSocket实时推送通知给相关用户
4. 用户可通过NotificationController查询历史通知

### 作业管理流程
1. 教师创建作业任务（TaskController）
2. 系统通知相关学生（NotificationService）
3. 学生查看并完成作业（TaskSubmissionController）
4. 教师批改作业并给出评价（TaskEvaluationController）
5. 系统通知学生查看评价结果（NotificationService）

### 考勤管理流程
1. 教师或系统记录学生考勤情况（AttendanceController）
2. 系统自动统计考勤数据（AttendanceService）
3. 异常考勤情况触发通知发送给家长（NotificationService）
4. 考勤数据用于学生评估和报表生成

### 即时通讯流程
1. 用户发起会话或在已有会话中发送消息（ChatController）
2. 消息通过WebSocket实时推送给接收方（WebSocketConfig）
3. 消息同时保存到数据库（ChatService）
4. 接收方可查询历史消息记录（ChatController）

1. **身份认证**：使用JWT进行无状态认证，避免会话劫持
2. **权限控制**：基于角色的访问控制，精确到方法级别
3. **数据加密**：敏感数据如密码使用BCrypt加密存储
4. **跨站防护**：配置CORS和CSRF防护
5. **输入验证**：所有用户输入经过严格验证，防止注入攻击
6. **日志审计**：记录关键操作，支持安全审计
7. **异常处理**：统一异常处理，避免泄露敏感信息
